Deliver `work-on`'s review gates through one immutable Review index instead of a monolithic review package. Every gate — initial cumulative, each remediation delta, and each fresh cumulative confirmation — creates a fresh input-only index from that gate's exact frozen inputs and dispatches the same index identity and pinned comparison/Candidate identities to Standards, Spec, and closure. Each axis begins by reading the authenticated gate assignment and the complete changed-path inventory, then adds only the frozen components its own obligation makes it responsible for (Standards the frozen Standards input, Spec the trusted contract, closure the contract, manifest, validation-evidence policy, and the indexed evidence records, read for their existing identities and safe provenance locators rather than by dereferencing raw payloads) and widens to any other frozen component a concrete review question requires, through the same verified read. A component or comparison that will not verify has no live substitute, and hard review-input failure, retriable delivery failure, and external-evidence inadequacy stay three distinct routes. Each axis binds its report to the exact Review-index identity and returns `COMPLETE` or `INCOMPLETE`; an `INCOMPLETE` axis cannot complete a gate, and availability to widen never discharges an inspection obligation. `scripts/review-index.sh changed-paths` adds the one new mechanical surface: it verifies the whole package first, then derives the complete raw no-renames changed-path inventory from the pinned trees with the ambient behaviors that can drop or rewrite an entry disabled at the invocation — replacement objects, rename inference, submodule ignoring, and relative narrowing — so a `refs/replace/*` ref, a configured rename or submodule-ignore setting, or a caller's subdirectory cannot change which paths a gate sees, and no stored artifact becomes a second changed-path authority. `manifest-identity.sh review-index-path` returns the governing Review-index script's path only after validating the Run's complete custody and its current governing-instruction identity, so a gate runs that script from the target repository rather than depending on a skill installation path, and a Run whose governing script has changed fails closed. `review-index.sh` joins `work-on`'s governing-instruction identity, so changing the executable review-input authority mid-run invalidates continuation exactly as the other governing inputs do. The default workflow and `SKILL.md` stop preloading the manifest, raw evidence, and evidence policy into the three review axes: readiness still receives them directly, while each review gate freezes the manifest, policy, and qualifying evidence records into its index. The index freezes evidence records, not raw evidence payloads: raw evidence stays at its safe provenance locator and is inspected there when an axis needs it.
