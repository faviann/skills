Add `work-on`'s Review-index package primitive. `scripts/review-index.sh create` takes explicit gate metadata, pinned comparison and Candidate commit/tree identities, and the caller's already-frozen trusted contract, review assignment, validation-evidence policy, Standards input, Validation-surface manifest, and zero or more evidence records, then publishes an owner-only temporary `work-on-review-index/v1` package whose index is written last and returns only that index's absolute path and expected SHA-256 once the package fully verifies. Identical inputs yield byte-identical components and index bytes regardless of the temporary package root, and each evidence record is addressed by the SHA-256 of the caller's own record so its existing Reusable-evidence identity and safe provenance locator stay inside the record rather than being restated by the package. One verifier serves creation and the public `verify` command: it independently enforces the required singleton roles, the canonical evidence-list shape, and every component digest, proves the authenticated index bytes are exactly the canonical serialization of the members it parsed rather than a form the shell normalized into one, rejects members whose locator is not the one canonical package-relative path, proves custody along the whole path rather than at the leaf alone, and requires each pinned commit to resolve to exactly itself and to its separately supplied tree with the gate kind agreeing with the comparison-base or Reviewed-anchor role. `read` resolves exactly one component through the authenticated index, hashes and emits one private snapshot of the bytes it captured, and emits nothing at all when verification fails, so it stays a range-free byte-exact cat that propagates failure through an ordinary `pipefail` pipeline. Changed-path discovery and diffs remain derived from the pinned Git trees rather than a stored authority component.
