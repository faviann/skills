Freeze a finite `work-on` Validation-surface manifest before implementation is delegated. The closability gate now accepts a criterion's direct-evidence population only as an explicit finite enumeration or a deterministic, non-interpretive selection rule that it evaluates during preflight, freezes the resulting manifest as recoverable owner-only run-local state identified with the exact trusted snapshot and pre-implementation base, and recomputes the whole preflight rather than patching one entry when an input changes. The selected workflow remains an invalidation input whose instruction identity belongs to Workflow provenance; it carries the manifest to the implementation delegate and every review context, keeps it bounding evidence rather than implementation, review, or same-mechanism investigation scope, and fails closed when a trusted criterion turns out to require an omitted member: `Closes` becomes unavailable, the omission is recorded and classified instead of remediated in-run, and the run hands back as `Progresses` or `failed`.
