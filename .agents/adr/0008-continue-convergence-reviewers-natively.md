# Continue convergence reviewers natively

To reduce repeated reorientation across closely related correction deltas without weakening independent confirmation, `work-on` retains each axis reviewer from a cumulative gate that produced an accepted blocker and continues it through the resulting correction chain using only the harness's native continuation mechanism, spawning a fresh reviewer for any axis that cannot continue, which then holds that axis for the remainder of the lineage, and inventing no persistence, handoff, or checkpoint mechanism. Reviewer memory is never authoritative: every gate is governed by its own distinct immutable **Review index**, reviewer-visible normative inputs are identical whether the reviewer is continued or freshly spawned, and no accepted-blocker, rejected-finding, or adjudication state reaches a reviewer, so a mixed continued/fresh triad is a valid gate and harness compaction can cost reconstruction work but never validity. A reviewer target that participated in an earlier gate of the current review lineage can never satisfy a later fresh cumulative-review requirement, so a Confirmation reviewer may become a Convergence reviewer and never the reverse. The #150 forensic disproved this issue's original premise that reviewer cold starts are a major cost driver — first-request ingestion averaged 17,793 tokens across 47 reviewer sessions, 1.8% of reviewer input — leaving the narrower hypothesis that axis-local continuity reduces repeated reorientation, which is to be observed on ordinary runs rather than promised here.
